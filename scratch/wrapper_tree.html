Mental Model

SCIGMA is packaged as Python, but most heavy work is in one compiled shared library: scigma/libscigma.so, scigma/libscigma.dylib, or scigma/libscigma.dll. Python modules do three jobs:

1. Load the compiled library

scigma/library.py resolves the platform-specific library and exposes lib.

2. Wrap C++ objects

Thin Python classes store integer handles named objectID and pass them into lib.scigma_* functions.

3. Provide a user command layer

Top-level modules register command dictionaries through plug(win) and are dispatched by Window.process_command().

4. Coordinate UI and tasks

Window, panels, graph objects, logs, and callbacks glue user input to numerical tasks.

Wrapper Tree

  • scigma/common/ shared wrappers

Startup Path

1. import scigmascigma/__init__.py runs immediately.
2. load liblibrary.py calls ctypes.CDLL() and sets LARGE_FONTS_FLAG.
3. create Windowmain = new(None) constructs Window, Log, GLWindow, and Console.
4. plug modulesequations.plug(), graphs.plug(), iteration.plug(), etc. install commands and panels.
5. event loopgui.application calls back into Window.loop_callback() to process queued commands and task logs.

ctypes Bridge

The Python wrapper is not a CPython extension module. It uses plain exported C symbols from a shared library. Each wrapper module imports lib, declares selected argtypes/restype, and calls into the compiled side. 

from ctypes import *
from .. import lib

lib.scigma_num_equation_system_parse.argtypes = [c_int, c_char_p]
lib.scigma_num_equation_system_parse.restype = c_char_p

result = lib.scigma_num_equation_system_parse(self.objectID, create_string_buffer(line))

Command Plugins

Most user-facing modules follow a consistent shape: a module-level commands dictionary maps abbreviations to Python functions, plug(win) registers the dictionary with the current Window, and unplug(win) removes module state. 

def plug(win):
    if not win.register_plugin('equations', lambda: unplug(win), commands):
        return
    # allocate panels, state objects, callbacks

def unplug(win):
    if not win.unregister_plugin('equations'):
        return
    # destroy panels and delete attributes

Risks And Gotchas

Importing scigma has side effects: it prompts for font size, loads the shared library, creates a graphics window, and registers callbacks. Avoid importing it in tooling that only wants static metadata.
  • objectID values are unmanaged integer handles. If a wrapper is destroyed twice or used after destroy(), Python cannot protect you.
  • CFUNCTYPE callback objects must stay referenced on the Python object. Several classes store them as self.c_callback; follow that pattern.
  • Many string paths assume ASCII and use create_string_buffer(bytes(...encode("ascii"))).
  • Some ctypes signatures are declared only partially. When adding calls, set both argtypes and restype explicitly.
  • Window.process_command() treats unknown commands as possible equations before trying option set/query behavior. New command names should avoid colliding with equation syntax or option names.
  • The CMake build links static subsystem libraries into one shared scigma target using whole-archive flags so the wrapper symbols are exported from the single library.
